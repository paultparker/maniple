Maniple spawn fix: readiness probe vs. oh-my-zsh update prompt

Produced 2026-09-09 21:37 CDT · First version · Repo: ~/Dropbox/code/maniple, merged to main as d4073dc

The bug (2026-09-09, 3 of 3 spawns failed)

When maniple spawns a worker it opens a fresh shell and types echo "MANIPLE_READY_7f3a9c" + Enter, then watches the pane for that marker on its own line. If it never appears within 10 s, spawn fails with "Shell not ready after 10.0s … Terminal may still be initializing."

oh-my-zsh's periodic update check prints Would you like to update? [Y/n] and does a one-keystroke read -r -k 1. When that prompt was already on screen, it ate the e. The shell then ran cho "MANIPLE_READY_…" → command not found. The marker never printed, the probe was never re-sent, and every subsequent worker shell hit the same prompt (answering with e does not record the check, so OMZ asks again next shell). Load was normal; the error text's "still initializing" hint pointed at the wrong cause.

OptionVerdictWhy
Set DISABLE_AUTO_UPDATE=true in the worker shell's environmentRejectedWorks on tmux (new-window -e) but iTerm launches the login shell from its profile with no pre-shell env hook → breaks backend parity. Also fixes only OMZ, not the class of "something ate a keystroke".
Edit ~/.zshrc to disable/auto the OMZ promptNot done (Paul's call)Config edit outside the repo; would also hide the fix's need. Optional belt-and-suspenders, see below.
Harden the probe: re-send on stall, both backendsChosenBackend-agnostic, no env plumbing, recovers from any one-shot keystroke eater. Plus the error now shows the last screen lines so the next such failure diagnoses itself.

What changed

  • New shared module src/maniple_mcp/shell_probe.py: probe_shell_ready() sends the echo, polls the screen every 0.1 s, and re-sends the probe if the marker hasn't appeared 2.5 s after the last send, until the overall timeout (still 10 s). Injectable clock/sleep so unit tests are instant. screen_tail() returns the last 8 non-blank screen lines.
  • tmux (terminal_backends/tmux.py) and iTerm (iterm_utils.py): their wait_for_shell_ready functions are now thin wrappers over the shared probe. Signatures and bool returns unchanged, so existing tests that patch them still pass.
  • Error message on both backends: Shell not ready after 10.0s in <path>. Last screen lines: followed by the pane tail. The misleading "Terminal may still be initializing" hint is gone.
  • Tests: tests/test_shell_probe.py (8, unit) and tests/test_shell_ready_parity.py (6, both backends: recovery from a swallowed probe, tail in the error, empty-screen fallback). Mutation-audited: disabling the resend branch fails exactly the swallowed-probe tests.
  • CHANGELOG.md Unreleased/Fixed entry.
